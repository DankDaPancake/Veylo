## Shared records and ownership
Performed by: Codex (AI-assisted draft). Reviewed by: pending (Thái Kiệt). Edited by: Codex.

| Record | Proposed fields and invariants | Producer and consumers |
| --- | --- | --- |
| Rider planning data | Approved role and hub plus an active-rider signal and configured positive capacity in kg and optional service-area context. Current PA3 User has role and hub but no active/capacity fields. Review storage and source with F03. | T05/F03 agree on source, F03 reads |
| Shift | ID, hub ID, assigned Rider ID, proposed state (DRAFT, PUBLISHED or COMPLETED), start/end instants, capacity snapshot in kg, version and publication instant (empty in draft). Recheck capacity on Rider replacement. Check overlap for the same Rider and hub, allowing adjacent windows. | F03 writes, F04/F05 read |
| ShiftStop | ID, shift ID, order ID, positive one-based sequence, version and proposed release timestamp. A published read orders live stops by sequence. Proposed uniqueness applies only to live rows for order ID and shift/sequence. Retain released stops for attempt history. Release timing remains D3. | F03 writes, F04/F05 read |
| Order | Keep the F02 order ID, hub ID, normalized code identity, version and current NEW/CANCELLED values. Persist window instants and use decimal strings for kg on the wire. | F02 writes intake. T05/F03/F04 coordinate lifecycle rules. |
| DeliveryAttempt | ID, hub/order/shift/stop IDs, executing Rider ID, state, Started/Arrived/Finished instants and outcome (null while active or aborted, proof reference and media type for success, reason and optional comment for failure). History retains its original assignment and Rider. At most one active attempt per order. | F04 writes, F03/F05 read relevant state |
| Failure resolution | Proposed record linking the failed attempt and order to the deciding Dispatcher, time, proposed decision label (REDISPATCH or TERMINAL_CLOSE), reason and destination stop for redispatch. Recheck eligibility and resolution state and recover a previously committed decision on replay. Persist the resolution and related assignment change together. | F04 writes, F03 coordinates reassignment |

F03 publishes eligible same-hub, unassigned NEW orders and checks aggregate weights against capacity. A failed attempt leaves the order open for dispatcher resolution. Treating every NEW row as eligible for a fresh assignment would bypass that resolution. The exact redispatch and assignment-release rule is pending under D3. Transfers check both shifts and versions in one transaction. An active attempt blocks an affected move, removal or Rider change. Completed shifts are read-only. F05 receives the authorized candidate list with ID, sequence, priority, delivery window, eligibility and coordinates when available. The F05 owner owns the ranking implementation and explanation under UC14. Distance inputs may include the last completed stop with known coordinates, falling back to configured hub coordinates if available. PA3 Hub has no coordinates field. Confirm the optional source with T08. Ranking is advisory and leaves the published sequence intact.

## Published read, Start and recovery
Performed by: Codex (AI-assisted draft). Reviewed by: pending (Thái Kiệt). Edited by: Codex.

The [v0.1 JSON fixtures](../../test/pa4-fixtures/f03-f04-contract-v0.1.json) illustrate independent cases and can feed mocks. T06–T08 can use the examples before the executable seed is approved. The examples use synthetic IDs, including one Dispatcher and two Riders in the same hub.

The example reads a selected published shift. Selection or listing across multiple published shifts remains for T06/T07 to agree. A draft is invisible to Rider reads. Dispatcher planning and resolution are scoped to the current hub. Rider execution is scoped to the Rider's own assignment. Administrator has no implicit Dispatcher or Rider access. A missing hub prevents scoped work. An optional guide preview may be absent.

The proposed Rider stop DTO maps PA3 Order columns as follows. `order_code` → `orderCode`, `recipient_name` → `recipientName`, `recipient_phone` → `recipientPhone`, `delivery_address` → `deliveryAddress`, `window_start`/`window_end` → `deliveryWindowStartsAt`/`deliveryWindowEndsAt`, `weight_kg` → decimal-string `weightKg`. Preserve `note`, `status` and `version`. Map known `latitude` and `longitude` to a numeric `coordinates` object with both keys. Use null when either value is unavailable. An authorized stop has `activeAttempt` null or the current attempt DTO as shown by the reload fixture. F05 receives ranking inputs only.

- Rider read uses the authenticated identity and current hub membership. Only the assigned Rider sees a published shift and its ordered stops. A caller with no visible published shift gets an empty result. Another Rider directly requesting a stop or attempting Start gets a generic denial with no target details. The 403 fixture illustrates Vision N05 for authenticated access denial. Missing or expired authentication is evaluated separately as 401.
- Start accepts the stop ID, observed shift and stop versions, and an operation request ID. The server resolves the order and actor from current records. Recheck assignment, hub, publication, eligibility and versions within the transaction. Proposed 409 STALE_ASSIGNMENT tells an authorized caller to refresh.
- Accept the first Start once. A retry after lost acknowledgement recovers the same attempt ID and Start instant. An assigned Rider revisiting a stop with an active attempt resumes it, including after reload. The fixture depicts an immediate replay without intervening state changes. Proposed Start returns 201 for creation and 200 for replay or resume. Scope the operation key to actor, order, action and clientRequestId. A different request ID on the same authorized active stop resumes the current attempt. A legitimate new Start after an ended attempt uses a new request ID and passes eligibility checks. Keep a separate database invariant for one active attempt. Re-authorize and resolve a valid replay before rejecting a now-stale version.
- Use a transaction and consistent lock acquisition for commands touching the same rider, shift, stop or order. If Start commits first, the affected reassignment is locked. If reassignment commits first, stale Start is rejected. Exact constraints, version updates and retry storage need schema review.
- Proposed wire states are STARTED and ARRIVED (active), plus SUCCESSFUL, FAILED and ABORTED (recorded outcomes). Require one readable JPEG/PNG up to 5 MB for success. Failure retains its reason. Proposed codes are UNREACHABLE, REFUSED, WRONG_OR_UNLOCATABLE_ADDRESS, UNSAFE_ACCESS and OTHER. Require a comment for Other and for pre-arrival failure. Pre-arrival failure is limited to an incorrect or unlocatable address or unsafe access. Dismissing a form keeps the attempt active. A separately confirmed abort records Aborted history, retains Arrived time if already recorded and restores eligibility when the assignment still applies. At three distinct Failed attempts, disable redispatch and keep the order open pending Dispatcher confirmation of terminal closure with a reason. Aborted attempts and replayed submissions do not contribute to the count.
